# REVIEW.md

List every defect found in the starter `app/main.py` (helpers and endpoints). For each one:

| # | Where (function / line) | What is wrong | How you'd notice it (test, input, or symptom) | How you fixed it |
|---|---|---|---|---|
| 1 | `health()` (line 73–74) | Does not actually ping MongoDB. Returns `{"status": "ok"}` unconditionally even if the database is down. | Stopping MongoDB and calling `/health` still returns 200. Should return 503. | Added `client.admin.command("ping")` inside a try/except; raise HTTP 503 on failure. |
| 2 | `list_employees()` – pagination skip (line 93) | `skip = page * page_size` is off-by-one. Page 1 should skip 0 rows, but this skips `page_size` rows, so the first page is empty and results are shifted. | Request page 1 with 5 employees; response returns 0 items. | Changed to `skip = (page - 1) * page_size`. |
| 3 | `list_employees()` – total count (line 94) | `total = db.employees.count_documents({})` ignores the `department` filter. When filtering by department, `total` always reflects the entire collection, breaking pagination metadata. | Filter by `department=Engineering` with 2 employees out of 10; `total` incorrectly shows 10. | Changed to `db.employees.count_documents(q)` so the filter is applied. |
| 4 | `create_employee()` – race condition (line 79–80) | Uses check-then-insert (`find_one` + `insert_one`). Under concurrent duplicate requests both can pass the check and insert two documents, or a 500 is thrown from a duplicate key violation instead of a clean 409. | Send two identical POST /employees at the same instant; may get 500 or two 201s. | Removed the pre-check; catch `DuplicateKeyError` from `insert_one` and return 409. The unique index on `emp_code` is what enforces uniqueness. |
| 5 | `create_employee()` – `created_at` timezone (line 82) | `datetime.now()` returns a naive datetime (no timezone). PyMongo stores it but comparisons and serialization are ambiguous. | Serializing to epoch milliseconds from a naive datetime can produce wrong values depending on system timezone. | Changed to `datetime.now(timezone.utc)` then truncated to whole seconds, so the value is UTC-aware and unambiguous. |
| 6 | `punch_in()` – employee existence not checked (line 101–102) | `db.employees.find_one(...)` is called but the result is never checked for `None`. If the employee doesn't exist, `emp["shift_start"]` raises a `TypeError` / `NullPointerError`, returning a 500 instead of a 404. | POST /attendance/punch-in with an unknown emp_code crashes with 500. | Added `if not emp: raise HTTPException(404, "Employee not found")`. |
| 7 | `punch_in()` – timestamp conversion (line 102) | `datetime.fromtimestamp(body.punched_at / 1000)` returns a **naive** datetime in the **local system timezone**, not UTC. Late-minutes and attendance-date calculations are then done against the wrong timezone. | On a machine with IST as local timezone, a UTC punch-in is shifted by 5h30m, causing wrong `date` and wrong `late_minutes`. | Changed to `datetime.fromtimestamp(ms // 1000, tz=timezone.utc)` to always get a UTC-aware datetime, and truncated to whole seconds (R1). |
| 8 | `punch_in()` – attendance date (line 103) | `ts.date().isoformat()` uses the naive local datetime, so the calendar date is wrong for UTC instants and completely incorrect for overnight shifts (R1 is not implemented). | An overnight employee (shift 22:00–06:00) who punches in at 01:00 IST gets the wrong `date`. | Implemented `attendance_date()` helper that converts to IST and applies the overnight-shift rule from R1. |
| 9 | `punch_in()` – `late_minutes` computation (line 113) | `compute_late_minutes` receives a naive `ts` datetime; comparing it to an IST-based `start` (also naive, built from `punch_in`) produces an incorrect delta because there is no timezone offset applied. Additionally the grace period logic uses `minutes > 10` (strictly greater), but R2 says 09:40:00 → 0, meaning the boundary is **not** late, which `> 10` handles incorrectly for fractional seconds. The floor division `int(... / 60)` should be `int(... // 60)`. | A punch-in at exactly 09:40:00 (10 minutes after shift_start 09:30) shows `late_minutes = 10` instead of 0. | Rewrote helper to use UTC-aware datetimes and IST-aware `shift_start_ist`; gate is `<= 10 * 60` seconds; floor via `int(delta_secs // 60)`. |
| 10 | `compute_overtime()` – naive date construction (line 46) | `datetime.fromisoformat(date_str).replace(hour=h, minute=m, tzinfo=IST)` is correct for a day shift, but completely ignores overnight shifts (shift_end on the *next* calendar day). This causes a large negative delta for overnight employees who punch out in the morning. | Overnight employee (22:00–06:00) punches out at 06:40 IST; overtime is calculated as large negative → clamped to 0, ignoring actual 40 min overtime. | Rewrote `compute_overtime_minutes()` to detect overnight shifts and add `timedelta(days=1)` to the shift-end date when needed. |
| 11 | `compute_work_hours()` – rounding (line 41) | `round(..., 2)` uses Python's banker's rounding (round-half-to-even), not half-up as required by R4. | Duration that gives exactly X.X25 seconds could round to the wrong value (e.g. 8.125 → 8.12 with banker's, should be 8.13). | Replaced with a `round_half_up()` helper using `math.floor(value * 100 + 0.5) / 100`. |
| 12 | `punch_in()` – response includes `"id"` field (line 119) | The starter sets `doc["id"] = str(res.inserted_id)` and then pops `_id`. The spec says `_id` is **internal and never returned**; there should be no id field in the response at all. | Response body contains `"id": "..."`, which is not in the OpenAPI schema. | Removed the line. Only `_id` is popped; a serializer converts the document to the correct API shape. |
| 13 | `list_attendance()` – loads entire collection (lines 144–146) | `list(db.attendance_logs.find(q))` fetches every matching document into Python memory, then sorts and slices in Python. On ~100 k records this is prohibitively slow and memory-intensive. The spec requires it to "stay fast". | With 100 k records the endpoint times out or uses gigabytes of RAM. | Pushed sort (`[("date", -1), ("emp_code", 1)]`) and pagination (`skip`, `limit`) into the MongoDB query so only the requested page is transferred. A compound index on `(date DESC, emp_code ASC)` is created at startup. |
| 14 | `list_attendance()` – mutates docs (line 149) | `d["id"] = str(d.pop("_id"))` mutates the returned document in place and adds an `id` field not in the schema. | Response contains `"id"` instead of never exposing `_id`. | Removed; serializer function handles output shape without exposing `_id`. |

## Things inspected and decided NOT to be defects

- The `IST` constant definition (`timezone(timedelta(hours=5, minutes=30))`) is correct.
- Using `body.model_dump()` in `create_employee` is the correct Pydantic v2 API (replaces `.dict()`).
- The `load_dotenv()` call at module level is fine and the expected way to load `.env`.
