# Employee Attendance & Analytics API

A FastAPI + MongoDB REST API for employee attendance tracking with business rules, manual corrections (with audit trail), and analytics.

## Requirements

- Python 3.11+
- MongoDB 6.0+ (local or Atlas)

## Setup

1. **Clone the repo** and enter the directory:
   ```bash
   cd hrone-attendance-api
   ```

2. **Install dependencies:**
   ```bash
   pip install -r requirements.txt
   ```

3. **Create a `.env` file** in the project root (do not commit this):
   ```
   MONGO_URI=mongodb://localhost:27017
   MONGO_DB=attendance_db
   ```
   Or set environment variables directly. If using MongoDB Atlas, use your SRV connection string.

4. **Run the server:**
   ```bash
   uvicorn app.main:app --port 8000
   ```

5. **API docs** (auto-generated by FastAPI):
   - Swagger UI: http://localhost:8000/docs
   - ReDoc: http://localhost:8000/redoc

## Endpoints

| Method | Path | Description |
|--------|------|-------------|
| GET | `/health` | MongoDB readiness probe |
| POST | `/employees` | Create an employee |
| GET | `/employees` | List employees (paginated, filterable by department) |
| POST | `/attendance/punch-in` | Record a punch-in |
| POST | `/attendance/punch-out` | Record a punch-out |
| GET | `/attendance` | List attendance records (paginated, filterable) |
| PATCH | `/attendance/{emp_code}/{date}` | Manually correct a record (with audit trail) |
| GET | `/analytics/employees/{emp_code}/monthly` | Monthly summary for one employee |
| GET | `/analytics/departments/summary` | Department-level summary for a month |
| GET | `/analytics/leaderboard/late` | Late-comers leaderboard for a month |
| GET | `/analytics/departments/{department}/trend` | Daily attendance trend for a department |
| GET | `/admin/explain/{endpoint}` | MongoDB explain plan for an endpoint's query |

## Business Rules Implemented

- **R1** – IST time zone for all dates; overnight shift detection (punch-in before shift_end → belongs to previous day)
- **R2** – Late arrivals with 10-minute grace period; `late_minutes` = floor minutes since shift_start
- **R3** – Overtime only when ≥ 30 minutes past shift_end; overnight shift_end on next calendar day
- **R4** – `work_hours` = (punch_out − punch_in) / 3600, rounded to 2 decimals half-up
- **R5** – `half_day` = true when `work_hours` < 4.50; counts as 0.5 present day
- **R6** – PRESENT, WFH, ON_DUTY count as present; ABSENT and LEAVE do not
- **R7** – Working days are Mon–Fri; mid-month joiners counted from `joined_on`
- **R8** – All reported numbers rounded 2 decimals half-up (rates: 4 decimals half-up)
- **R9** – Headcount includes all employees with `joined_on ≤ end of period`, even those with zero logs
- **R10** – Pagination: page starts at 1, page_size max 100 (default 20)

## What is complete

All endpoints in `openapi.yaml` are implemented:
- `/health` with real MongoDB ping
- Employee CRUD (create + list)
- Punch-in and punch-out with all business rules
- Regularize (manual correction) with full audit trail and optimistic concurrency
- All four analytics endpoints with MongoDB aggregation pipelines
- `/admin/explain/{endpoint}` for query plan inspection

Indexes are created at startup (idempotent):
- Unique index on `employees.emp_code`
- Unique compound index on `attendance_logs.(emp_code, date)`
- Compound indexes for list/sort queries and analytics range scans

## Notes

- Instants are stored as BSON datetimes (UTC), served as epoch milliseconds at the API boundary.
- Calendar dates and shift times are stored and served as plain strings (no timezone ambiguity).
- Punch times are truncated to whole seconds (R1).
- The `.env` file is excluded from version control — do not commit secrets.
